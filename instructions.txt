===============================================================================
 KALACHAKRA — the complete run
 From install to a trained model over all 10,256 years, to every visual
===============================================================================

This is the end-to-end operator's guide. Follow it top to bottom for a full
production run, or jump to a part with the table of contents. Every command here
is real and runnable; nothing is a placeholder.

Kalachakra computes the solar system's geometry over an exact 10,256-year
timeline (Kali Yuga epoch 3102 BCE -> 7154 CE), projects it onto a geodesic
Earth mesh, compresses it with a Spherical Autoencoder + Spatio-Temporal Fourier
Neural Operator into a 64-d latent manifold, tokenizes and indexes it for
deep-time queries, and renders it through a losslessly-invertible isomorphic
transducer. The outputs are objective geometry (angular separations, resonance /
tension, latent norms, rarity, cluster labels) — never interpreted text.

===============================================================================
 PART 0 — Two scales, and what you get at each
===============================================================================
There are two ways to run everything. The pipeline, the models, and all the
visuals are identical; only the data span and the compute differ.

  (Q) QUICK SCALE — Moshier backend, NO data files.
      The Swiss Ephemeris "Moshier" analytic backend ships inside pyswisseph and
      needs no downloads, but is only valid ~1900 BCE .. 4650 CE. That already
      covers all of recorded history and the present. Trains in minutes on a
      laptop CPU. Use this to learn the whole flow and see every visual today.

  (F) FULL SCALE — the entire 10,256-year timeline.
      3102 BCE and the far future fall OUTSIDE Moshier, so you plug a long-range
      ephemeris (Swiss .se1 / DE431, or raw JPL DE441) into the Swiss Ephemeris
      (Part 3). The full G(t) matrix is ~13.4 billion 24-second frames (~300 GB)
      and the full macro-harmonic training cycle is a ~90-day run on an M4 Max.

Everything below is written so the SAME commands work at both scales: add
`--ephe-path` / `--jpl-file` (or run the one-command setup in 3.1, after which no
flags are needed) to go full scale.

===============================================================================
 PART 3 — Integrate the FULL 10,256-year span (the ephemeris)
===============================================================================
Skip this part for a QUICK-scale run. Do it once for FULL scale.

A note on DE431 vs DE441: the ready-made Swiss ".se1" files (OPTION A) are built
from JPL DE431, which spans ~13000 BCE .. 16800 CE and therefore already covers
Kalachakra's entire 3102 BCE .. 7154 CE timeline. DE441 is JPL's newer long
integration; over this span the two agree far below the arc-second level
(immaterial for a topological simulation). DE441 ships only as raw ".bsp"
kernels (OPTION B). OPTION A is the practical full span; OPTION B is the literal
DE441 route. The code supports both.

-------------------------------------------------------------------------------
 3.1 — One-command setup (recommended)
-------------------------------------------------------------------------------
A single script downloads exactly the right files, verifies it can compute the
3102 BCE epoch, and writes a config so EVERY later command uses the full span
automatically — no flags to remember:

  python scripts/setup_full_span.py

That fetches the 36 needed Swiss .se1 files (~40 MB) to ~/.kalachakra/ephe from
the official Swiss Ephemeris GitHub mirror (aloistr/swisseph), and writes
./.kalachakra.json. After it finishes, go straight to generation/training with
no backend flags:

  python scripts/train.py --store data/full     # picks up the full span from config

Useful flags:
  --dry-run           show the exact file list, download nothing
  --dest DIR          download location (default ~/.kalachakra/ephe)
  --config-path PATH  where to write the config (default ./.kalachakra.json)
  --configure-only    do not download; just verify + configure an existing DIR
  --mirror-all        fetch every .se1 block, not only the needed set
  --base-url URL      alternative source (e.g. https://www.astro.com/ftp/swisseph/ephe)
  --jpl               fetch the raw JPL DE441 .bsp kernels instead (OPTION B)
  --no-verify         skip the epoch-computation check
  --no-config         download only; do not write the config file

MANUAL DOWNLOAD, then automatic setup — the reliable fallback if any download is
blocked on your network: download the files yourself (see 3.2 for the exact
list), put them all in one folder, and let the script verify + configure it:

  python scripts/setup_full_span.py --dest /path/to/your/folder --configure-only

-------------------------------------------------------------------------------
 3.2 — OPTION A: Swiss Ephemeris .se1 files  (the practical full span)
-------------------------------------------------------------------------------
How the filenames work (verified against the official docs):
  * Each .se1 file covers exactly 600 years.
  * Prefix = body group:  sepl = planets (Mercury..Pluto),  semo = Moon.
    (seas = asteroids — NOT needed. Kalachakra uses Sun/Moon/planets + the lunar
    nodes Rahu/Ketu only, so you need sepl* and semo* and nothing else.)
  * Suffix = 600-year block. "_NN" = CE, "mNN" = BCE, number x 100 = century:
        sepl_00 = 1 BCE .. 599 CE     seplm06 = 601 BCE .. 2 BCE
        sepl_18 = 1800 .. 2399 CE     seplm36 = 3601 BCE .. 3002 BCE

You need 18 planet blocks + the matching 18 Moon blocks = 36 files, ~40 MB:

  base=https://raw.githubusercontent.com/aloistr/swisseph/master/ephe
  blocks="m36 m30 m24 m18 m12 m06 _00 _06 _12 _18 _24 _30 _36 _42 _48 _54 _60 _66"
  mkdir -p ~/ephe/se1 && cd ~/ephe/se1
  for b in $blocks; do
      wget "$base/sepl$b.se1"   # planets
      wget "$base/semo$b.se1"   # Moon
  done

Block -> year coverage (sepl* and semo* share these blocks):
    m36 : 3601 BCE .. 3002 BCE   <- contains the 3102 BCE Kali Yuga epoch
    m30 : 3001 BCE .. 2402 BCE       m06 :  601 BCE ..    2 BCE
    m24 : 2401 BCE .. 1802 BCE       _00 :    1 BCE ..  599 CE
    m18 : 1801 BCE .. 1202 BCE       _06 ..  _60 : 600 .. 6599 CE (600-yr steps)
    m12 : 1201 BCE ..  602 BCE       _66 : 6600 CE .. 7199 CE  <- contains 7154 CE end

Alternative sources:
  * Sparse-clone the whole ephe/ folder (contains the complete long-range set):
        git clone --depth 1 --filter=blob:none --sparse https://github.com/aloistr/swisseph
        cd swisseph && git sparse-checkout set ephe
    then use --ephe-path .../swisseph/ephe
  * astro.com FTP: https://www.astro.com/ftp/swisseph/ephe/  (set base= to it in
    the loop above; if a file 404s there, use the GitHub mirror).

Point Kalachakra at the directory with --ephe-path (Part 3.4 onward), or let
setup_full_span.py --dest ~/ephe/se1 --configure-only record it once.

-------------------------------------------------------------------------------
 3.3 — OPTION B: JPL DE441 .bsp kernels  (the literal DE441)
-------------------------------------------------------------------------------
Use this only if you specifically want the raw JPL DE441 integration.

  mkdir -p ~/ephe/jpl && cd ~/ephe/jpl
  base=https://naif.jpl.nasa.gov/pub/naif/generic_kernels/spk/planets
  curl -O $base/de441_part-1.bsp   # ~1.3 GB, 13201 BCE .. 1969 CE
  curl -O $base/de441_part-2.bsp   # ~1.3 GB, 1969 CE .. 17191 CE

The Swiss Ephemeris reads ONE JPL file at a time and our timeline straddles both
parts, so generate the pre-1969 CE portion with part-1 and the post-1969 CE
portion with part-2 (two runs, different --jpl-file), or concatenate them with
SPICE tooling if you have it. OPTION A avoids this split entirely.
(`python scripts/setup_full_span.py --jpl` downloads both parts for you.)

 3.4 — Verify the backend reaches 3102 BCE

Confirm you can compute a date Moshier cannot — the Kali Yuga epoch:

  # If you ran setup_full_span.py, no flags are needed (config is picked up):
  kalachakra reading --date -3101-02-18

  import os
  from kalachakra.ephemeris import global_state as gs
  gs.configure(mode="swiss", ephe_path=os.path.expanduser("~/ephe/se1"))
  print(gs.global_state_frame(588465.5).shape)   # Kali Yuga epoch -> (10, 7)
  PY

===============================================================================
 PART 4 — Generate the ephemeris matrix G(t)   (~300 GB, segmented)
===============================================================================
The generator writes BF16 + delta-encoded, memory-mapped chunk files. At QUICK
scale you can skip this — train.py auto-generates a small store for you. For FULL
scale, pre-generate G(t) in segments so you can checkpoint and parallelize.

4a. A bounded real segment starting at the Kali Yuga epoch (frame 0):

    python scripts/generate_ephemeris.py \
        --out data/full --ephe-path ~/ephe/se1 \
        --start-frame 0 --max-frames 100000000 --chunk-frames 1000000

    (Use --jpl-file ~/ephe/jpl/de441_part-1.bsp instead of --ephe-path for
     Option B; if you ran setup_full_span.py, both flags are optional.)

4b. Start a segment at a date instead of a frame index:

    python scripts/generate_ephemeris.py --out data/full \
        --start-date -3101-02-18 --max-frames 100000000

4c. The WHOLE timeline (very large — do it in many segments, e.g. one 600-year
    block at a time, on fast SSD). Omit --max-frames to run to the end:

    python scripts/generate_ephemeris.py --out data/full \
        --start-frame 0 --chunk-frames 1000000

    Resume a partial generation by setting --start-frame to the next frame after
    the last chunk already written (chunk dirs are named by their start frame).


===============================================================================
 PART 5 — Train and SAVE the model
===============================================================================
The training script is turn-key. With NO store present it generates a real one
and trains immediately, then SAVES reloadable models.

QUICK scale — one command, no data files, no arguments:

  python scripts/train.py

That will: (1) generate a real store under data/store (Moshier), (2) build the
geodesic mesh + STFNO spherical autoencoder, (3) train with Lion + cosine-
annealing warm restarts in BF16, printing the composite geodesic loss as it
falls, and (4) write checkpoints under ./checkpoints/ (see APPENDIX for the exact
filenames):
    micro_latest.pt     resumable (weights + optimizer + scheduler)
    model_latest.pt     latest self-contained model (reload for inference)
    model_final.pt      final self-contained model

Add the tokenizer (needed for the deep-time index in Part 6) with --quantize;
this trains the Autoencoder + hierarchical residual VQ together and saves a
quantized checkpoint:

  python scripts/train.py --quantize

FULL scale — train against the store you generated in Part 4, on the full mesh.
(If --store is missing it will be generated first; pass --ephe-path / --jpl-file
so that generation uses the full span, or rely on the saved config from 3.1.)

  python scripts/train.py \
      --store data/full --ephe-path ~/ephe/se1 \
      --nodes 122880 --window 64 --stride 32 --batch 4 \
      --hidden 128 --blocks 3 --modes 32 \
      --quantize --epochs 1 --save-every 500 --checkpoints checkpoints/full

Resume an interrupted run from the newest resumable checkpoint:

  python scripts/train.py --store data/full \
      --resume checkpoints/full/micro_latest.pt

Apple M4 Max full-scale notes (blueprint §1.4):
  * Training auto-selects the MPS device on Apple Silicon.
  * Use the full mesh: --nodes 122880.
  * Keep BF16 mixed precision (default) to fit the ~80 GB unified-memory budget.
  * The complete macro-harmonic cycle over the full timeline is a ~90-day run;
    step checkpoints here plus the Trainer's era snapshots make it restartable.


===============================================================================
 PART 6 — Build the tokenized deep-time index  (tier1/2/3 + rarity)
===============================================================================
build_index.py streams real ephemeris -> projects -> encodes -> quantizes to
discrete geometric tokens (64 macro x 64 micro = 4096 leaves) -> computes the
deep-time Rarity Index -> writes the full three-tier temporal mipmap to
century-partitioned Parquet indexed by Uber H3:
    tier1 = native 24 s frames
    tier2 = hourly (150-frame) rollups
    tier3 = daily / epochal (3600-frame) rollups + anomaly counts

Requires:  pip install -e ".[train,index]"

Best tokens — from the quantized model you trained in Part 5:

  python scripts/build_index.py \
      --out data/index --quantized-checkpoint checkpoints/full/model_final.pt \
      --nodes 256 --frames 3000

Other modes:
  --checkpoint model_final.pt   a plain-AE checkpoint wrapped with a fresh RVQ
  (neither flag)                a fresh untrained model — the full data path still
                                runs so you can exercise indexing end to end

Add --ephe-path / --jpl-file (or use the 3.1 config) to index far-past/future
windows. The DuckDB router then routes any viewport query across tier1/2/3 by
span and velocity (Parts 7.2, 8).

-------------------------------------------------------------------------------
 7.1 — WebGL cosmic-weather globe   (web/index.html)
-------------------------------------------------------------------------------
A rotating point-cloud globe coloured by per-node geometric potential/shear.

Requires:  pip install -e ".[serve]"

  # Serve the REAL weather field for an instant + the globe page, same origin:
  python scripts/serve.py --date 2024-04-08T18:17 --nodes 8000 --port 8000
  #   -> open  http://127.0.0.1:8000/ui/index.html

The page pulls its field in this order: (1) a precomputed ./heatmap.json if
present, else (2) the live broadcast API (/heatmap, /potential), else (3) a
synthetic fallback. So you have two ways to feed it:

  A) Live from geometry (no model), as above with serve.py. Point queries too:
       curl 'http://127.0.0.1:8000/potential?lat=48.85&lon=2.35'

  B) From a precomputed field written next to the page:
       kalachakra map --date 2024-04-08T18:17 --nodes 8000 --out web/heatmap.json
     then open http://127.0.0.1:8000/ui/index.html (served by any serve.py), or
     open web/index.html directly from disk.

  C) From the TRAINED latent model (potential/shear from the 64-d manifold):
       python scripts/analyze.py --checkpoint checkpoints/full/model_final.pt \
           --date 2024-04-08T18:17 --ephe-path ~/ephe/se1 --out web/heatmap.json
     (analyze.py loads a plain, non-quantized checkpoint. Reuse the plain
      model_final.pt from a `train.py` run without --quantize, or train once
      without --quantize specifically for analysis/globe fields.)

FULL scale: serve.py honors the saved full-span config, so a far-past date works:
  python scripts/serve.py --date -3101-02-18 --nodes 8000 --ephe-path ~/ephe/se1

-------------------------------------------------------------------------------
 7.2 — Isomorphic transducer radar   (web/radar.html)
-------------------------------------------------------------------------------
The physics-based client: a global sphere whose surface is spherical-harmonic
topography from the latent, lit by Planckian colour temperature (rarity),
Naka-Rushton radiant flux (magnitude), an orthonormal visible-spectrum mix (the
four temporal bands), and a Helmholtz-Hodge + Line-Integral-Convolution flow
shell (the vector field), with a diurnal terminator sweep. Dual viewport +
Sidebar Inspector.

Requires:  pip install -e ".[index,serve]"   (+ ".[cluster]" for HDBSCAN labels)

  # 1) Build an index (Part 6). 2) Serve the radar API + page, same origin:
  python scripts/serve_radar.py --index data/index --port 8000
  #   -> open  http://127.0.0.1:8000/ui/radar.html

Inside the page:
  * It streams binary field frames over the WebSocket (ws://HOST:PORT/stream);
    if the socket is down it renders a synthetic field so the page always draws.
  * DOUBLE-CLICK any point -> Sidebar Inspector: it calls /telemetry and shows
    the raw numerics (timestamp, rarity percentile, VQ archetype, the four band
    energies, each body's Cartesian unit vector + radial distance + angular
    velocity, applying/separating, eclipse state).
  * SHIFT + DOUBLE-CLICK -> the regional micro-canvas: it calls /microgrid and
    computes a continuous-LOD weather field over just that bounding box (§4).

The same server also answers, for scripting or a custom UI:
  * POST /inspect   tier-routed rows + band gains + mean latent + manifold
                    clusters (cluster_id per row, n_clusters, method)
  * POST /news      the rarest events in a viewport as textless geometric news
                    cards (body vectors, applying/separating, dominant aspect,
                    rarity percentile — no interpreted text)
  * GET  /health    which tiers are populated
See Part 8 for curl examples.

-------------------------------------------------------------------------------
 7.3 — The isomorphic transducer itself   (Python, losslessly invertible)
-------------------------------------------------------------------------------
The rendering is an objective sensory converter, not decoration: the optical
state is a lossless storage medium for the latent field. You can round-trip it in
Python to machine precision.

Requires:  pip install -e ".[transducer]"   (scipy, for the SH topography)

  python - <<'PY'
  import numpy as np
  from kalachakra.transducer.state import IsomorphicTransducer
  t = IsomorphicTransducer()
  latent = np.random.default_rng(0).normal(size=64)          # a 64-d latent
  bands  = np.abs(np.random.default_rng(1).normal(size=4))   # 4 temporal bands
  optical = t.transduce(latent=latent, band_energies=bands, rarity=0.7, potential=1.3)
  back    = t.invert(optical)
  print("latent recovered to:", np.max(np.abs(back["latent"] - latent)))  # ~1e-15
  PY

The web radar (7.2) mirrors this exact math in GLSL/JS; the Python transducer is
its oracle. See docs/06_isomorphic_transducer.md for the full mapping table and
the invertibility bounds.

-------------------------------------------------------------------------------
 7.4 — gRPC control plane   (serve_grpc.py)
-------------------------------------------------------------------------------
The strongly typed counterpart to the REST/WebSocket app — the same engine, the
CosmicWeather service (Health / Inspect / Telemetry). Contract:
proto/kalachakra.proto (committed stubs in kalachakra.serving.grpc_gen).

Requires:  pip install -e ".[grpc,index]"

  python scripts/serve_grpc.py --index data/index --port 50051

  python - <<'PY'
  import grpc
  from kalachakra.serving.grpc_gen import kalachakra_pb2 as pb, kalachakra_pb2_grpc as pbg
  stub = pbg.CosmicWeatherStub(grpc.insecure_channel("127.0.0.1:50051"))
  print(stub.Health(pb.HealthRequest()))
  r = stub.Inspect(pb.InspectRequest(min_lat=-90, min_lng=-180, max_lat=90,
      max_lng=180, start="2000-01-01T12:00:00Z", end="2000-01-01T15:00:00Z", limit=20))
  print(r.tier, r.n_rows, dict(r.band_gains))
  PY

(To change the contract, edit proto/kalachakra.proto and regenerate the stubs —
the command is in that file's header. grpcio-tools is in the [grpc] extra.)

===============================================================================
 PART 9 — Full-scale checklist (disk, MPS, the ~90-day cycle)
===============================================================================
Disk budget (put it all on a fast SSD):
    ephemeris data files      ~40 MB (.se1)      or  ~2.6 GB (DE441 .bsp)
    generated G(t) matrix      up to ~300 GB for the full timeline
    checkpoints                a few GB
    tokenized Parquet index    depends on nodes x frames indexed

Recommended full-scale sequence:
    1.  python scripts/setup_full_span.py                     # Part 3.1
    2.  kalachakra reading --date -3101-02-18                 # Part 3.4 verify
    3.  python scripts/generate_ephemeris.py --out data/full \
            --start-frame 0 --chunk-frames 1000000           # Part 4c (segmented)
    4.  python scripts/train.py --store data/full --quantize \
            --nodes 122880 --hidden 128 --blocks 3 --modes 32 \
            --window 64 --stride 32 --save-every 500 \
            --checkpoints checkpoints/full                    # Part 5 (MPS, ~90 d)
    5.  python scripts/build_index.py --out data/index \
            --quantized-checkpoint checkpoints/full/model_final.pt \
            --nodes 122880                                    # Part 6
    6.  python scripts/serve_radar.py --index data/index      # Part 7.2 radar
        python scripts/serve.py --date -3101-02-18 --nodes 8000   # Part 7.1 globe
        python scripts/serve_grpc.py --index data/index          # Part 7.4 gRPC

Interrupted? Resume training from checkpoints/full/micro_latest.pt (Part 5).
Generation resumes by advancing --start-frame (Part 4c).

    micro_latest.pt            newest RESUMABLE (weights+optimizer+scheduler)

    model_latest.pt            newest self-contained model (for inference)

    model_step_<step>.pt       periodic self-contained snapshots
    (with --quantize these self-contained files hold the AE + trained RVQ; pass
     model_final.pt to build_index.py --quantized-checkpoint)
    Use micro_latest.pt for --resume; use model_final.pt for analyze/build_index.
